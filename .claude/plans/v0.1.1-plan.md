**Per-row deliverable — one atomic PR per row (or small row groups), each containing ALL of:**
1. The table row: capability, product, risk class, **status from the legend**, primary-source URL (allowed host), last-verified date = the date the source was actually fetched.
2. A `### Row N — …` details section mirroring rows 1–5: what it does, **status evidence with verbatim status-bearing quotes**, caveats/scope boundaries, config reality.
3. **`sources.json` registration for every allowed-host URL the row and its details section cite** (row 4 cites three URLs — expect the same shape), with `cite_url` exactly equal to the cited URL; a Roadmap-status row additionally gets a roadmap-mode entry with its `feature_id`. Row 12's source is registered **human-only** per D3.
4. **The watcher baseline for the new sources: run `python scripts/watch_sources.py --update-baseline` and commit the resulting `fingerprints.json` in the same PR.** (A plain run writes nothing — it is read-only detection; an uncommitted baseline makes every subsequent daily watch fire the adjudicator on "first observation".)
5. Matrix table-heading row count updated (`## The matrix (v0.1.x — N rows, expanding)`).

Hard rules: a source that conflicts with itself or another primary source → **Requires further validation**. Roadmap-only → **Roadmap** with feature ID. Nothing from launch blogs or Tech Community. Two failed fetch attempts → defer per D5.

## 5. Risks & mitigations

| Risk | Mitigation |
|---|---|
| **Fabricated verification** (a date written without a fetch) — the repo's cardinal sin | Implementation prompt requires evidence quotes captured at fetch time; adversarial verify pass re-fetches every cited URL and matches quotes before the PR is marked ready |
| Model "knows" a status from training data and writes it without fetching | Hard rule: training-data knowledge is never citable; only same-day fetched text counts |
| Learn page unfetchable / render-gated | Use the raw MicrosoftDocs mirror pattern from `sources.json`; two attempts then defer the row (D5) |
| Citation containment fails a row PR | Atomicity rule in WS1 (row + sources + baseline in one PR) makes the failure structurally impossible; CONTRIBUTING documents it for humans |
| D3 widens the automation trust surface / non-Microsoft content reaching the adjudicator | D3(b): docs.github.com source is human-only — never fetched by the watcher, never machine-adjudicated; smallest-possible regex; full mirror-wording list changed together |
| Unbaselined sources make the daily watch fire the adjudicator ("first observation" churn) | `--update-baseline` committed in the same PR as each registration |
| CHANGELOG restructure silently redirects future bot entries into released history | D2 mechanics: no released heading may contain the word "refresh"; dry-run acceptance criterion |
| Scope explosion (7 deep rows) | D5 priority order + two-fetch deferral rule; v0.1.2 is an honest landing zone |
| Checklist/README/CHANGELOG drift (the 35-day-drift failure mode already seen) | P4 consistency pass with its own acceptance criteria; pre-existing drift items enumerated in WS4 |
