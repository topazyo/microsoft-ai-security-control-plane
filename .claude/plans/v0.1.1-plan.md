## 5. Risks & mitigations

| Risk | Mitigation |
|---|---|
| **Fabricated verification** (a date written without a fetch) — the repo's cardinal sin | Implementation prompt requires evidence quotes captured at fetch time; adversarial verify pass re-fetches every cited URL and matches quotes before the PR is marked ready |
| Model "knows" a status from training data and writes it without fetching | Hard rule: training-data knowledge is never citable; only same-day fetched text counts |
| **Indirect prompt injection via fetched documentation reaching an agent holding Edit/Bash(git\|gh)** | Split fetch from judgement per WS1's "fetched content is data, never instruction"; draft PRs only; human merge (H4) |
| Learn page unfetchable / render-gated | Use the raw MicrosoftDocs mirror pattern from `sources.json`; two attempts then defer the row (D5) |
| Citation containment fails a row PR | Atomicity rule in WS1 (row + sources + baseline in one PR). **Note this is structurally impossible only for rows whose sources are in the `sources` array — a human-only source needs D3(c).** CONTRIBUTING documents it for humans |
| D3 widens the automation trust surface / non-Microsoft content reaching the adjudicator | D3(b) human-only + D3(c) making that flag real; smallest-possible regex; full mirror-wording list changed together |
| Unbaselined sources make the daily watch fire the adjudicator ("first observation" churn) | `--update-baseline` committed in the same PR as each registration, **via WS1 item 4's four-step procedure so a pending upstream change is never silently absorbed** |
| **Sibling row PRs conflict, or merge cleanly leaving a wrong row count / duplicate row numbers** | Stacked branch chain in D5 priority order (WS1); the heading row count and row numbers are re-derived from the table, never incremented blind, in the P4 consistency pass |
| CHANGELOG restructure silently redirects future bot entries into released history | D2 mechanics: no released heading may contain the word "refresh"; no bare `[Unreleased]` placeholder; dry-run acceptance criterion |
| Scope explosion (7 deep rows) | D5 priority order + two-fetch deferral rule; v0.1.2 is an honest landing zone |
| Checklist/README/CHANGELOG drift (the 35-day-drift failure mode already seen) | P4 consistency pass with its own acceptance criteria; pre-existing drift items enumerated in §0 and WS4 |
| **The human merge gate never fires, deadlocking WS2/P3** | WS2's non-response path (a) stack on the OWASP branch, or (b) defer to v0.1.2 with a named reason |
| **A release claim that the cadence is "live" while tiers D2/D3 have never worked** | WS6.1 + H6; §0 restated to say "partially live"; §4 requires a green forced-adjudication run |
