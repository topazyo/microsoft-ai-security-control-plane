## Non-negotiable invariants (apply to every stage)

1. **Fetch-before-status.** No release-status label is ever written, changed, or "confirmed" from your training knowledge. A status may only be asserted from a primary source you fetched **in this session**, and the row's last-verified date must be the date of that fetch. If you cannot fetch it, you cannot claim it.
2. **Evidence quotes.** Every status you assert must be backed by a verbatim status-bearing quote captured from the fetched page and written into the row-details section, following the exact pattern of existing rows 1–5 in `matrix/capability-status-matrix.md`.
3. **Conflict → Requires further validation.** If a source conflicts with itself or with another primary source, the row is labelled **Requires further validation** — never resolved by judgement. A row is never moved *out* of that label by you (escalation-direction rule; in-tenant confirmation by a human is required).
4. **Never guess framework IDs.** CSA AICM control IDs are registration-gated and human-only: every AICM cell you touch says "not yet mapped" unless a human has supplied the ID. MITRE ATLAS IDs must be verified against the distributed `atlas-data` dataset. OWASP items use **LLM0x:2026** numbering per the renumbering table that lands with the plan's WS0 merge — never 2025 IDs, and never a 2026 ID inferred from a 2025 one without the table.
5. **Confidentiality.** Obey `.claude/rules/security.md` in full — no tenant identifiers, GUIDs, emails, hostnames, IPs, Message Center content, or registration-gated material, in files **or commit messages**. Everything you write will be public.
6. **Git discipline.** Work in your own worktree on fresh `feat/`- or `chore/`-prefixed branches off `main`. Never modify the existing `chore/owasp-llm-top-10-2026` branch (you will open a PR *from* it, unchanged). Small, reviewable commits. Open **draft PRs**; never merge anything; never push tags. Every item in the plan's §6 human-only register stays human.
7. **Atomic row PRs.** The citation-containment check (`scripts/validate_bot_pr.py:244–268`) hard-fails any PR whose matrix cites an allowed-host URL not yet registered. Every row PR must therefore contain, in one diff: the row + details section, the `sources.json` entries for **every** allowed-host URL the row cites, and the watcher baseline refreshed via `python scripts/watch_sources.py --update-baseline` (a plain run writes nothing). Verify the baseline run reports no `[warn]`/failed_sources lines for the new ids — the watcher exits 0 even on total failure, so the exit code is not evidence.
8. **Validators are the definition of done.** Before marking any PR ready: `python -m compileall -q scripts`, `python scripts/validate_bot_pr.py --base-ref origin/main`, and `python scripts/stale_guard.py` (expect exactly one knowingly-stale item: the CSA AICM framework row, unless a human completed the workbook lookup) must all pass locally, and the `Validate matrix` workflow must be green on the PR.
