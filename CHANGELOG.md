# Changelog

All notable changes to this repository are recorded here.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project follows a **monthly refresh cadence**: every row in the capability-status matrix is re-verified against Microsoft Learn and the Microsoft 365 Message Center each month, and every verification pass is recorded below (date, rows touched, status changes).

## [0.1.1] — 2026-08-10

**The first tagged, public release.** v0.1.0 was built locally and never tagged; this release supersedes it and discharges its release gate. The matrix grows from 5 rows to 9, the cross-walk is re-based on the OWASP 2026 edition and completed against the CSA AICM workbook, and the repository gains the licensing, contribution and security scaffolding a public release needs.

### Added

- `matrix/capability-status-matrix.md` — **four new capability rows, all verified against Microsoft Learn on 2026-08-10**, each with its source registration and watcher baseline landing in the same change:
  - **Row 6 — DSPM for AI licensing prerequisites: Requires further validation.** Microsoft's licensing references are **circular** — the DSPM considerations page names no SKU and defers to the Microsoft Purview service description, which defers back to the DSPM article. A reader following Microsoft's own links cannot determine the entitlement. What Learn *does* state specifically is recorded (a Microsoft 365 Copilot license for the Copilot/agent scope; the enterprise version of Purview data governance for the Fabric and Security Copilot scope; pay-as-you-go billing for other AI apps).
  - **Row 7 — DSPM for AI default posture: Requires further validation.** The posture itself is quoted verbatim and unambiguous — discovery policies cover all users "in audit mode only", the one blocking policy ships "in test mode", and only the weekly SharePoint risk assessment runs with "No activation needed". **DSPM for AI audits by default; it does not block by default.** The label reflects that the pages carrying that evidence are the version Learn calls *classic* and says is replaced, with no primary source establishing that the default carries over.
  - **Row 8 — Defender for Cloud Apps generative-AI app discovery: GA.** No preview qualifier and no release-state sentence across six pages read; "Generative AI" is a first-class catalog category among "over 31,000 discoverable cloud apps". Two caveats that cause real coverage-map errors are recorded: Microsoft Learn never uses the phrase "shadow AI" and has no article dedicated to this capability, and macOS support is stated on two pages while a third describes the mechanism as Windows-only.
  - **Row 9 — Sentinel Microsoft Copilot logs connector: Requires further validation.** A page-level notice states all Sentinel data connectors "are currently in Preview" while the same page suffixes only *some* entries "(Preview)" and the Microsoft Copilot entry carries none. Both signals cannot be authoritative. Also recorded: the connector is named "Microsoft Copilot" and spans Security Copilot, so matching it to a Microsoft 365 Copilot control is a judgement, not a quotation.
- `crosswalk/framework-crosswalk.md` — rows 6–9 mapped at item level using **2026 OWASP numbering**, with MITRE ATLAS technique IDs read from the distributed `atlas-data` dataset (v5.6.0) rather than recalled; `AML.T0024` Exfiltration via AI Inference API joins the cited techniques. Three of the four mappings carry a caveat that matters more than the cell contents: row 6 is a prerequisite rather than a control, row 7 is detective rather than preventive, and row 9 is a telemetry surface that mitigates nothing on its own.
- **CSA AICM mappings completed** — every previously unmapped cell is now resolved against the **AICM v1.1.1** workbook (generated 2026-07-22): row 5 → **AIS-15** Prompt Differentiation; row 7 → **DSP-17** Sensitive Data Protection and **UEM-11** Data Loss Prevention; row 8 → **UEM-02** Application and Service Approval; row 9 → **LOG-12** Transaction/Activity Logging and **LOG-03** Security Monitoring and Alerting. Row 6 is explicitly *not mapped* — a licensing prerequisite is not a control objective. The workbook is registration-gated and is **never committed to this repository**; only control IDs, titles and domain labels are reproduced, with attribution.
- **Release scaffolding** — `LICENSE` (MIT, covering `scripts/` and `.github/workflows/`), `LICENSE-CONTENT` (CC BY 4.0, covering the documentation content, and recording what neither license covers), `CONTRIBUTING.md`, `SECURITY.md`, `docs/scope-and-out-of-scope.md`, `.github/ISSUE_TEMPLATE/new-row-proposal.md`, `.github/ISSUE_TEMPLATE/status-correction.md`, and `.github/pull_request_template.md`.
- `.claude/plans/` — the v0.1.1 work plan and its implementation prompt, carrying the review log for both adversarial review passes.

### Changed

- `crosswalk/framework-crosswalk.md` — re-based on the **OWASP Top 10 for LLM Applications 2026 edition** (see the consolidated 2026-08-09 pass below), and the CSA AICM row advanced from v1.1.0 to **v1.1.1** on a genuine re-verification: the 247-control / 18-domain count was re-derived by direct count, and the workbook's Change Log confirms v1.1.1 altered only the Mappings, Implementation Guidelines and AI-CAIQ tabs, so no cited ID changed.
- `checklists/capability-status-verification.md` — **Version 1.3**. Groups 3, 5 and 7 extended with the 2026-08-10 findings, dated **per bullet** rather than per group, because `stale_guard.py` parses a single footer stamp per file and per-group dates are therefore not expressible. The footer now names which groups shipped and which deferred — **including Group 4**, whose Defender XDR advanced-hunting row the previous footer omitted. Group 3's expectation of an "E5 / E5 Compliance" citation is marked **unverified**, because current Learn documentation does not support it.
- `.github/workflows/validate-matrix.yml` — path filters widened to `docs/`, `README.md`, `disclaimer.md`, `CONTRIBUTING.md`, `SECURITY.md`, `LICENSE*` and the issue/PR templates. `check_confidentiality` scans every changed `.md`/`.json` file, so a scaffolding- or README-only pull request previously received **no confidentiality scan at all** — the check was absent rather than green.
- `checklists/capability-status-verification.md` — Group 1 told practitioners to record a **Message Center URL** as a row's primary source. Message Center posts have no public URL, the validator rejects the host, and the checklist's own Group 9 says to record the MC ID only. Corrected.
- `README.md` — pre-existing drift fixed: "three" DLP-for-Copilot rows where the matrix has four; the "8-group" checklist which has nine; and a structure tree that omitted the entire v0.1.0 automation surface (`scripts/`, the workflows, the watch state, the issue templates and the cadence doc). The License and contributing section now describes the dual license.

### Fixed

- `.github/workflows/stale-guard.yml` — the weekly guard had **never executed once**, and its first scheduled run would have failed: it creates its issue with `--label stale-rows`, and that label did not exist in the repository. The label was created and the workflow dispatched to confirm the path works end to end.

### Deferred to v0.1.2, with reasons

- **GitHub Copilot policy management row** — its primary source (`docs.github.com`) is outside the validator's allowed source hosts, and the human-only source registration that would admit it has no working configuration: `human_only_sources` is read by no script, so citation containment cannot be satisfied without a code change.
- **Defender XDR advanced-hunting row** and **Entra Conditional Access for AI workload identities row** — not reached in the v0.1.1 verification pass; no status asserted rather than an unverified one.
- **MCP governance gap section** — to be recorded as a documented gap rather than a status-labelled row.
- **Framework-source watch coverage** — `sources.json` registers no OWASP, ATLAS or NIST entry, so no automation can detect a framework-edition change. This is how the OWASP 2026 edition went unnoticed. The schema change needed to fix it properly is deferred.

### Known gaps at release

- **Cadence tiers D2 and D3 are non-functional.** The repository has no Actions secrets, so `secrets.ANTHROPIC_API_KEY` renders empty and the adjudication and monthly-refresh jobs cannot run. Tier D1 (daily source watch) and tier D4 (weekly stale guard) run on the auto-provided token and are working.
- **In-tenant verification remains open** for rows 1, 2, 3, 5, 6, 7 and 9, and for macOS discovery on row 8. These are documented open items, not silent ones — every affected row says so.
- The 2026-08-07 stamps on matrix rows 1–5 age out on **2026-09-07**.

### Verification passes consolidated into this release

- **2026-08-09 — OWASP framework-edition update.** `crosswalk/framework-crosswalk.md` re-based on the **OWASP Top 10 for LLM Applications 2026 edition (v1.0**, published 2026-08-03 by the OWASP GenAI Security Project**)**, superseding the 2025 (v2.0) edition. Only **LLM01 Prompt Injection and LLM02 Sensitive Information Disclosure retained their 2025 numbers**. A **2025 → 2026 renumbering table** was added, because every other slot changed occupant: Supply Chain LLM03→LLM04, Data and Model Poisoning LLM04→LLM05, Improper Output Handling LLM05→LLM10, Excessive Agency LLM06→LLM03, Vector and Embedding Weaknesses LLM08→LLM09, Misinformation LLM09→LLM07, Unbounded Consumption LLM10→LLM06, and **System Prompt Leakage (LLM07:2025) renamed and re-scoped as LLM08:2026 Hidden Context Exposure**. The artifact read was confirmed byte-identical to OWASP's published download by SHA-256. Two caveats recorded: the released v1.0 PDF prints **no publication date** (its title page still carries an unfilled "[Publication date to be set]" placeholder), and the `genai.owasp.org/llm-top-10` landing page **still presented the 2025 edition** at verification time. A note on the 2026 edition's **Appendix A: Related Framework Mappings** was added, recorded as OWASP's own work and explicitly neither a validation nor an endorsement of this repository's synthesis. MITRE ATLAS, NIST AI 600-1 and CSA AICM stamps were deliberately left untouched — none was re-read in that pass.
- **2026-08-07 — monthly re-verification.** All four existing rows re-verified against Microsoft Learn and the Microsoft 365 Roadmap; **every status held**. Row 3 (typed-prompt SIT blocking) **stayed Requires further validation**: the Learn heading had dropped the "(preview)" qualifier it carried on 2026-07-14 while the body of that same section still read "This feature is in preview and is rolling out to all tenants" — a conflict inside a single page, not evidence of GA. Row 1: Learn no longer carried the "extends to prebuilt agents" sentence, so prebuilt-agent coverage is no longer claimed from that source. Row 4: recorded the availability table's "Connected AWS accounts: No", and that the table does not enumerate AI-agent protection. **Row 5 added** — external-email grounding block, **Public Preview**. Group 9 added to the checklist. The **automated refresh cadence** landed in this pass: `.github/workflows/` (daily source watch with event-gated adjudication, monthly consolidating refresh, weekly stale guard, deterministic validation gate), `scripts/`, `.claude/agents/`, `.github/watch-state/sources.json`, and `docs/agent-cadence.md`. The Microsoft 365 Message Center and the CSA AICM workbook were recorded as permanently human-only sources.
- **2026-07-14 — monthly re-verification.** All four rows re-verified against Microsoft Learn and the Microsoft 365 Roadmap; every status held. Last-verified stamps advanced from 2026-07-03.
