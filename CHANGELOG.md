# Changelog

All notable changes to this repository are recorded here.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project follows a **monthly refresh cadence**: every row in the capability-status matrix is re-verified against Microsoft Learn and the Microsoft 365 Message Center each month, and every verification pass is recorded below (date, rows touched, status changes).

## [0.1.2] — 2026-08-10

**Four deferred rows land, two subsystems close long-standing blind spots, and four of this repository's own published claims are corrected.** The matrix grows from 9 rows to 13, the cross-walk graduates to **v0.2** with every cell resolved, the source registry gains framework-edition watching — the gap that let the OWASP 2026 edition go unnoticed — and the planned-rows backlog carried since v0.1.0 is fully discharged.

The date above is both the verification date for every row in this release and the date the `v0.1.2` tag was cut — they coincide because the release was cut on the day the verification pass ran. **Do not read that as a rule.** In this repository a heading date means the date the sources were actually re-read; when a release is tagged later than its verification pass, the two will differ and the heading follows the tag while each row keeps its own last-verified date. See "How rows are verified".

### Added

- `matrix/capability-status-matrix.md` — **three new capability rows, all verified against primary sources on 2026-08-10 and then re-verified by an independent pass that re-fetched every cited URL:**
  - **Row 10 — prompt-injection signals reaching Defender advanced hunting: GA (email channel); AI-agent surface Public Preview.** The row exists to correct a common coverage-map assumption: **there is no advanced-hunting surface for Microsoft 365 Copilot chat prompts.** What exists is two adjacent surfaces with different release states — prompt injection carried in *email*, via Defender for Office 365, which does reach advanced hunting as a detection-technology property and carries no preview qualifier; and *AI-agent* telemetry, explicitly public preview. Also recorded: the AI agent inventory table is mid-migration and the older table's stated availability date has already passed.
  - **Row 11 — Conditional Access for workload identities: GA; agent-user targeting Public Preview.** Two independent Learn pages state the scope boundary in near-identical words — single-tenant service principals registered in your tenant only, with Microsoft and third-party SaaS applications *including multitenant apps* not covered, and managed identities not covered. Recorded as the limit that decides whether this control is worth anything for AI workloads: an agent authenticating with an API key bypasses Entra ID entirely and no policy applies.
  - **Row 12 — GitHub Copilot policy management: Requires further validation.** The precedence *mechanics* are quoted and confirmed; the release *state* is not establishable. The one "generally available" sentence on these pages scopes to MCP server support rather than to policy management, preview wording appears on the same pages, and two cited sources hedge the multi-enterprise rule differently. **The first row in this matrix whose primary source is not Microsoft Learn or the Microsoft 365 Roadmap.**
  - **Row 13 — enterprise governance of MCP servers: GA (managed-settings allowlist); private-registry enforcement Public Preview.** **This row was planned as a documented gap and shipped as a control**, because the verification found one. A non-overridable enterprise allowlist/denylist now exists, defined in an enterprise `managed-settings.json`, matching on "name, URL, or `stdio` commands", evaluated deny-first, and failing closed on a malformed or unretrievable policy. The residual gap is stated precisely rather than dropped: client coverage is limited to the clients that support that settings file and is "Planned to expand in the near future", third-party hosts are explicitly excluded, built-in default servers are a permanent carve-out, and the alternative private-registry method is public preview and documents its own bypass.
- `scripts/validate_bot_pr.py`, `scripts/watch_sources.py` — **GitHub Docs admitted as a primary source, human-only** (decision D3, deferred from v0.1.1). `docs.github.com` joins the allowed source hosts, is registered under `human_only_sources` so the watcher never fetches it and no GitHub page content reaches the adjudicator, and `human_only_sources` becomes something code actually reads — it had been inert JSON, which is exactly why the row was blocked. Human-only URLs travel in a **separate `human_only_citation_urls` bundle key** rather than being merged into `allowed_citation_urls`: merging them would let an automated run cite a page nothing ever fetched, which is the failure citation containment exists to prevent.
- `scripts/watch_sources.py` — **framework-edition watching** (decision D7, deferred from v0.1.1). A new `mode: "version"` extracts and fingerprints the version or edition tokens a framework publishes. Registering framework sources under the existing modes would not have worked: the signal extractor sees headings, preview qualifiers and nine fixed status phrases, none of which changes when an edition is republished — a source that reports "unchanged" forever while the registry claims coverage. **MITRE ATLAS** and **OWASP** are registered; **NIST AI 600-1 is deliberately not**, being a static dated PDF whose successor would appear at a new URL no fingerprint of the old one could see, and is recorded human-only with that reason.
- `.github/watch-state/sources.json` — nine new entries: six Microsoft Learn sources backing rows 10 and 11, two framework sources, and four `docs.github.com` pages registered human-only for row 12.

### Fixed

- **The `human_only_sources` flag had no effect on anything.** Two coupled defects in the fix that was drafted for it: the natural spelling of the lookup, `s.get("cite_url", s["url"])`, evaluates its default eagerly and raises `KeyError` on exactly the entry shape it targets — a source that is never fetched has no fetch URL; and patching only citation containment's registry branch would have left every automated run failing, because with `--evidence` the check takes its allow-set from the bundle, which is the branch both bot paths use.
- `scripts/watch_sources.py` — `re.error` added to the failure-isolation tuple. It subclasses `Exception` directly, so a malformed `version_pattern` — or the `relevance_filter` compile that has always been there — would have aborted every source rather than one. The registry is now also checked for structural faults before the loop, which is the one condition this script is meant to fail on: a fetch failure is expected and isolated, a broken registry is neither.

### Corrected after independent verification

An independent pass re-fetched all eleven URLs cited by the new rows and tested every quote against the page it is attributed to. **It reopened all three rows.**

- **Row 10's label rested on a conflict that does not exist.** The covered-services list read as contradicting another page is explicitly illustrative — introduced as logs from connected apps "such as:" — so an omission from it is silence, not denial, and the two pages reconcile through the same connector. The row was relabelled and the false rationale removed. **Silence is not contradiction**, and "sources conflict" must be earned rather than reached for.
- **Row 11 cited a verbatim quote to a page that does not contain it.** This is the same cross-attribution defect corrected in v0.1.1. The per-quote attribution rule did not prevent it; the re-fetch did. The correct page is now cited and registered.
- **Row 12's GA basis did not survive**, and the row moved to Requires further validation.

### Known gaps at release

- **The planned-rows list is empty.** That is a statement about the backlog, not about coverage: Microsoft's AI-security surface is far larger than thirteen rows. It means nothing is sitting half-verified. New rows arrive through the new-row proposal template, on the same terms as the existing ones.
- **Row 13's client coverage is unverified here.** The page enumerating which clients support the enterprise settings file was not read on this pass, so "supported clients" is quoted rather than enumerated. Confirm it before relying on the allowlist's reach.
- **Cadence tiers D2 and D3 still cannot run in CI.** No `ANTHROPIC_API_KEY` is configured. Both are gated on key presence and defer with a green run and a loud warning rather than failing red. A green scheduled `Source watch` is not evidence that adjudication works.
- **The in-tenant verification gate was closed by the maintainer on 2026-08-10**, covering rows 1, 2, 3, 5, 6, 7, 9, 12 and 13, macOS discovery on row 8, row 10's hunting schema and columns, and row 11's agent-targeting options. **No row status changed as a result, and that is not an oversight.** Closing the gate records that a human made the check; it is not itself evidence of what the check found. A row leaves **Requires further validation** only on a specific documented finding, cited and dated like any other — so rows 3, 6, 7, 9 and 12 hold their labels here, and would move only in a later pass that records what was observed and where. The four contested sub-questions those rows rest on are unchanged by this: Learn's own pages still disagree with themselves or each other on each one.
- The 2026-08-07 stamps on matrix rows 1–5 and the NIST cross-walk row age out on **2026-09-07**.

## [0.1.1] — 2026-08-10

**The first tagged, public release.** v0.1.0 was built locally and never tagged; this release supersedes it and discharges its release gate. The matrix grows from 5 rows to 9, the cross-walk is re-based on the OWASP 2026 edition and completed against the CSA AICM workbook, and the repository gains the licensing, contribution and security scaffolding a public release needs.

### Added

- `matrix/capability-status-matrix.md` — **four new capability rows, all verified against Microsoft Learn on 2026-08-10**, each with its source registration and watcher baseline landing in the same change:
  - **Row 6 — DSPM for AI licensing prerequisites: Requires further validation.** Microsoft's licensing references are **circular** — the DSPM considerations page names no SKU and defers to the Microsoft Purview service description, which defers back to the DSPM article. A reader following Microsoft's own links cannot determine the entitlement. What Learn *does* state specifically is recorded (a Microsoft 365 Copilot license for the Copilot/agent scope; the enterprise version of Purview data governance for the Fabric and Security Copilot scope; pay-as-you-go billing for other AI apps).
  - **Row 7 — DSPM for AI default posture: Requires further validation.** The posture itself is quoted verbatim and unambiguous — discovery policies cover all users "in audit mode only", the one blocking policy ships "in test mode", and only the weekly SharePoint risk assessment runs with "No activation needed". **DSPM for AI audits by default; it does not block by default.** The label reflects that the pages carrying that evidence are the version Learn calls *classic* and says is replaced, with no primary source establishing that the default carries over.
  - **Row 8 — Defender for Cloud Apps generative-AI app discovery: GA.** No preview qualifier and no release-state sentence across six pages read; "Generative AI" is a first-class catalog category among "over 31,000 discoverable cloud apps". Two caveats that cause real coverage-map errors are recorded: Microsoft Learn never uses the phrase "shadow AI" and has no article dedicated to this capability, and macOS support is stated on two pages while a third describes the mechanism as Windows-only.
  - **Row 9 — Sentinel Microsoft Copilot logs connector: Requires further validation.** A page-level notice states all Sentinel data connectors "are currently in Preview" while the same page suffixes only *some* entries "(Preview)" and the Microsoft Copilot entry carries none. Both signals cannot be authoritative. Also recorded: the connector is named "Microsoft Copilot" and spans Security Copilot, so matching it to a Microsoft 365 Copilot control is a judgement, not a quotation.
- `crosswalk/framework-crosswalk.md` — rows 6–9 mapped at item level using **2026 OWASP numbering**, with MITRE ATLAS technique IDs read from the distributed `atlas-data` dataset (v5.6.0) rather than recalled; `AML.T0024` Exfiltration via AI Inference API joins the cited techniques. Three of the four mappings carry a caveat that matters more than the cell contents: row 6 is a prerequisite rather than a control, row 7 is detective rather than preventive, and row 9 is a telemetry surface that mitigates nothing on its own.
- **CSA AICM mappings completed** — every previously unmapped cell is now resolved against the **AICM v1.1.1** workbook (generated 2026-07-22): row 5 → **AIS-15** Prompt Differentiation; row 7 → **DSP-17** Sensitive Data Protection and **UEM-11** Data Loss Prevention; row 8 → **UEM-02** Application and Service Approval; row 9 → **LOG-12** Transaction/Activity Logging and **LOG-03** Security Monitoring and Alerting. Row 6 is explicitly *not mapped* — a licensing prerequisite is not a control objective. The workbook is registration-gated and is **never committed to this repository**; only control IDs, titles and domain labels are reproduced, with attribution.
- **Release scaffolding** — `LICENSE` (MIT, covering `scripts/` and `.github/workflows/`), `LICENSE-CONTENT` (CC BY 4.0, covering the documentation content, and recording what neither license covers), `CONTRIBUTING.md`, `SECURITY.md`, `docs/scope-and-out-of-scope.md`, `.github/ISSUE_TEMPLATE/new-row-proposal.md`, `.github/ISSUE_TEMPLATE/status-correction.md`, and `.github/pull_request_template.md`.

- **GitHub Copilot policy management row** — its primary source (`docs.github.com`) is outside the validator's allowed source hosts, and the human-only source registration that would admit it has no working configuration: `human_only_sources` is read by no script, so citation containment cannot be satisfied without a code change.
